2. Field units & semantics

  • Prices: fixed-point dollar strings ("0.4500") with up to 4 dp; quantities: _fp strings with 2 dp — per Fixed-Point Representation. This site displays them as $ and ¢ without inventing precision.
  • Order book: bids only (orderbook_fp.yes_dollars / no_dollars = [price_dollars, count_fp], ascending, best bid last). YES ask ≡ 1 − best NO bid (official reciprocal rule) — per Orderbook Responses.
  • Liquidity shown is computed bid-side notional (Σ price × contracts over both sides) — the demo responses observed do not include the legacy liquidity field; where absent we leave it blank elsewhere.
  • “Est. traded $” = contracts × last price. The API publishes contract volume but no per-market dollar-notional field in demo responses; this is our estimate, always labeled.
  • REST market responses are cached by the exchange for a short time — prices lag the tape by seconds — per Get Markets and Market Data Quick Start.

3. Alert rule (the two chats)

On every watchlist poll (~12 s) each market's sampled price (last trade, falling back to best YES bid when no trade) is compared with the previous sample in whole 1/10000-dollar units (so an exact $0.66 → $0.56 move, which binary float renders as 0.09999…, still fires). If the change is ≥ $0.10 in either direction, an alert is posted to the all-events chat. A 45-second per-market cooldown stops oscillation from spamming the chats. Only sampled deltas are used: we do not claim causality, and we do not infer moves that happened between polls (REST lag — flagged). Implemented in assets/app.js → checkAlert().

Model chat (high-ROI screen) — an alert is also posted when the score below clears the threshold (default 0.45):

score = 0.30·min(vol24h / 2000, 1)
      + 0.25·min(volume  / 10000, 1)
      + 0.20·max(0, 1 − spread/0.15)
      + 0.25·min(|Δ| / 0.25, 1)

Inputs are exchange-reported fields (contracts volume, quotes). The weights are engineering choices documented here — not verified predictive alpha (flagged). Implemented in assets/model.js → score().

Fee verification — the published table, reproduced exactly

Our fee function reproduces every row of the schedule’s “General Trading Fees Table” (21 prices × 1 contract and × 100 contracts). The check runs automatically in tests/root_engine.test.js on every push and pull request. It found and fixed a real bug: the naive float expression ceil(0.07·C·P·(1−P)·100) gave $1.76 for 100 contracts @ $0.50 (binary float renders 1.75 as 175.00000000000003), while the official table says $1.75 — the function now computes in integer arithmetic.

6. Chart windows & order book

  • Seconds (60 s, 5 m, 15 m): live session samples from REST polling (one point per poll ≈ 12 s).
  • Minutes/hours (1 h): exchange 1-minute candlesticks (trade-price close) merged with the live tail.
  • Hours (6 h, 24 h): exchange 60-minute candlesticks merged with the live tail.
  • Y axis: contract price $0.00–$1.00 (probability). X axis: time. Candlesticks are “a few seconds behind” per official docs, and demo markets trade sparsely, so hour+ windows can contain only a few candles. ≥ $0.10 alert markers are plotted as dots on the line; the latest jump in the window is linked below the chart (Kalshi market + news-search lead, causality never claimed).
  • Order book: YES bid/ask and NO bid/ask ladders show contracts available at each price (bids are exchange-published; asks are derived by the reciprocal rule). We request ?depth=10 (official parameter: the best 1–100 levels per side, counted from the best bid) and show the 6 best of each. Computed bid-side liquidity (Σ price × contracts) is labeled computed. Source: Get Market Orderbook.

7. Rate-limit care

Unauthenticated public requests have their own (undocumented) limits; the client backs off exponentially on HTTP 429, polls while the tab is visible only, batches tickers ≤200 per request, and pauses polling when hidden. See Rate Limits and Tiers.
