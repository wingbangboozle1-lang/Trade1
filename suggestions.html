How to make the dashboard more live and interactive

These are product suggestions, not verified data. Where a suggestion relies on an official Kalshi capability, the official doc is linked. Nothing here changes how the dashboard works today, and nothing is financial advice.

1. What the build already does (baseline)

  • Live REST polling of the public demo Trade API (~12 s watchlist, ~8 s selected order book, ~6 min topic discovery).
  • Two scrolling alert chats: all ≥ $0.10 moves, plus a model-picks feed filtered by a documented ROI score.
  • Interactive price chart with 60 s / 5 m / 15 m / 1 h / 6 h / 24 h windows (X = time, Y = contract price).
  • Order-book depth panel with computed bid-side liquidity (contracts at each price).
  • Resolution tracking until each watched market settles YES or NO.
  • Automated paper strategies (momentum, fade, harvest, breakout) with portfolio P&L by strategy and topic.
  • Per-row source links on the Data page; every unverified item left blank and listed on Flagged.

2. High-impact suggestions

#SuggestionWhy it helps a traderWhat it needs
1 WebSocket streaming (ticker, orderbook_delta, trade channels) Removes REST polling lag entirely; sub-second price and depth updates. Demo API keys — the official WS handshake requires signed auth headers a browser cannot attach (Quick Start: WebSockets). Demo WS endpoint already pinned in config.
2 Browser notifications + sound on ≥ $0.10 jumps Traders can watch other tabs while the site listens; jump alerts become actionable instantly. Notifications API (no backend needed) — the jump detector already exists in assets/app.js → checkAlert.
3 Sparklines in every table row A 60-second price shape per market makes the ranking table scannable without clicking through. Mini-canvases fed from the same local price history (S.history in assets/app.js).
4 Strategy backtesting on candlestick history Test parameter tweaks against weeks of official 1-minute / 1-hour candles before running live-in-paper. GET candlesticks already integrated (≤ 5,000 periods per request — Get Market Candlesticks).
5 Real demo-account execution (paper → live demo fills) Closes the loop: strategies place genuine demo orders; the portfolio page shows the true demo balance and P&L. A human-owned demo account + API key, then signed order placement per Authenticated Requests. Deliberately not implemented here (no credentials requested — flagged).

3. Medium-impact suggestions

#SuggestionWhy it helps a traderWhat it needs
6 Jump → news matching feed Replace labeled news *searches* with auto-fetched headlines per jump so a trader sees a plausible cause. A small serverless proxy (e.g., a GitHub Action committing JSON) since browsers cannot fetch arbitrary RSS cross-origin; each headline labeled unverified.
7 Cross-market arbitrage scanner Within an event, YES + NO asks below $1.00 implies a risk-free pair; flags mispriced multi-candidate events. Already-fetched orderbooks; add a math pass per event group.
8 Trade velocity + large-trade highlights Trades-per-minute and whale-trade flags explain jumps better than price alone. GET /markets/trades already integrated; aggregate client-side per market.
9 PWA + offline cache Installable mobile dashboard; last snapshot viewable offline (clearly timestamped as stale). Service worker + manifest; a static site makes this trivial.
10 Keyboard command palette Press "/" to jump to any market; number keys to switch topics — power-trader ergonomics. Pure front-end; no API dependency.

4. Continuous organization & simplification

  • Keep topics separate. One subpage per topic (gas / elections / culture / crypto / golf); never mix events across topics.
  • One-click triage. The landing page ranks the highest estimated-dollar markets so a trader decides in seconds where to look; topic pages hold the depth.
  • Simplified charts. Single price line by default, depth collapsed to best levels; detailed views on demand.
  • Everything sourced. Every table row links the exact API call plus the official Kalshi market page, so review never blocks the trading flow.
  • Flagged items stay visible. A persistent "Flagged" nav entry keeps unverified values one click away.
