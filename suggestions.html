3. Continuous organization & simplification

  • Keep topics separate. One subpage per topic (gas / elections / culture / crypto / golf); never mix events across topics.
  • One-click triage. The landing page ranks the highest estimated-dollar markets so a trader decides in seconds where to look; topic pages hold the depth.
  • Simplified charts. Single price line by default, depth collapsed to the best levels; detailed views on demand.
  • Everything sourced. Every table row links the exact API call plus the official Kalshi market page, so review never blocks the trading flow.
  • Flagged items stay visible. A persistent “Flagged” nav entry keeps unverified values one click away.

4. Trader's playbook (one page)

  1. Start on the Dashboard, pick one topic tab. The ranked table is highest-dollar first; ignore thin books (wide spread, near-zero 24h volume) — most ≥ $0.10 flickers live there.
  2. Read the left chat for facts, the right chat for opinion. Left = observed moves with API links. Right = the same moves filtered by the documented ROI screen (Methods §3). The screen is a heuristic, not verified alpha — treat it as a shortlist, not a signal.
  3. Click the alert, check the chart + book. Confirm the jump appears in the chart markers, then check contracts at each price in the order book. If depth is empty, the move is not tradable at size.
  4. Check the links before believing a cause. Each alert links the Kalshi market page, the event's official settlement sources, and a news search labeled “lead”. Causality is never asserted — verify the source yourself.
  5. Let the Strategy Lab run, then judge by category. Compare P&L by strategy and by topic (Strategy Lab). A strategy that only works in one topic is a topic bet, not a strategy.
  6. Track to resolution. Watched events flip to YES/NO automatically; paper positions settle at $1 per winning contract. Review closed trades against the resolution log before changing any parameter.
