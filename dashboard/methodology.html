Methodology & sources

Every number on this site comes from a documented endpoint or a documented formula. This page states which, so any value can be re-derived or challenged.

Kalshi docs — Market SettlementYES outcome pays YES holders $1 per contract, NO outcome pays NO holders $1; settlement fees are zero for simple yes/no determinations.

GET …/series?category=… and GET …/search/tags_by_categories
Liquidity
GET …/markets/{ticker}/orderbook?depth=10
History
GET …/series/{series}/markets/{ticker}/candlesticks (1/60/1440-minute bars)

GET …/markets/{ticker} → result
Demo account
GET https://external-api.demo.kalshi.co/trade-api/v2/portfolio/balance (signed)

The demo account is read through the recommended demo root from Kalshi's documentation. Public reads use the production shared endpoint because the demo market list is not a mirror of production prices.

Suggestions to make the site more live and interactive

  • Push updates instead of polling. Kalshi's WebSocket ticker channel would cut the delay from 15 minutes to under a second. It requires a signed handshake, so it becomes possible the moment demo credentials exist; until then polling is the honest option.
  • Alert on the move, not on the clock. Fire the ≥ $0.10 rule as soon as it happens and put it in the browser tab title, so the dashboard can be left open in the background.
  • One-line "why" column. Add a manual attribution entry (with a source link) next to each jump. The page already renders confirmed causes; the next step is a review queue.
  • Compare strategies on one axis. Overlay equity curves per strategy so the underperformer is obvious without reading tables.
  • Settlement countdown. Sort the markets page by time-to-close with a countdown, since most trader decisions are driven by expiry, not by volume.
  • Keep the charts boring. One price line, one liquidity bar set, no dual axes. The zoom presets (1m → 7d) already cover the useful ranges.

Verification rules applied to this site

  • Every value is copied from an API response or computed from copied values with a stated formula.
  • Missing values render as an em dash and appear on Flagged for review. Nothing is interpolated, back-filled or inferred.
  • Topic membership uses Kalshi's published fields only. The one editorial addition (requiring "gas" in a gas-price series title) is disclosed as a rule on the flagged page.
  • Each market row links to its API object and its Kalshi site page.
