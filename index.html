Executive summary

What this is. A static, read-only web dashboard over the official Kalshi demo Trade API (v2). It watches live markets in five topics — gas prices, elections, culture, crypto, and golf — posts a chat alert whenever a market's sampled price moves $0.10 or more in either direction, shows interactive price charts (seconds / minutes / hours windows) with per-price contract depth from the official order book, and runs an automated paper-trading lab that tests documented strategies and tracks a simulated portfolio until events resolve YES or NO.

  • Live data, no credentials. All market data comes from public, unauthenticated demo endpoints (verified: source list). CORS was probed from a GitHub runner on 2026-11-20 — the demo API reflects any browser origin (data/cors.json), so the page polls the API directly.
  • Two scrolling alert chats. Left: every ≥ $0.10 move across in-scope events. Right: the same feed filtered by a documented ROI screen (momentum magnitude, 24h volume, spread) — formula in Methods. Each alert links the official Kalshi market page, the event's official settlement sources, and a news-search lead. Causality is never claimed.
  • Resolution tracking. Watched markets are re-checked on every poll; when the exchange settles them, the outcome (YES/NO, settlement time, settlement value) is recorded, and paper positions settle at $1 per winning contract.
  • Strategy lab. Four automated paper strategies (momentum, fade, favorite-harvest, 50¢ breakout) run on live quotes; performance is categorized by strategy and topic with equity, win rate, and ROI tables. Trades persist in the browser (export/import available).
  • Verified snapshots. A GitHub Actions pipeline (scripts/collect.py) re-verifies the API and refreshes data/ snapshots twice hourly after deploy, with a per-request log (data/log.md) — every table row on the Data page links the exact official URL it came from.
  • Fees modeled from the official schedule. Paper P&L applies the official taker fee roundup(0.07 × C × P × (1−P)) from kalshi.com/docs/kalshi-fee-schedule.pdf (verified this session; maker fees not modeled — flagged).
  • Not implemented on purpose. No account login, no order placement, no WebSocket (browsers cannot attach Kalshi's required signed handshake headers), no dollar figures presented as exchange-published (traded-notional values are labeled estimates). Full list on Flagged for Review.

Scope: demo environment only (play money). Demo prices and behavior may not match production markets — treat all analysis as methodology, not trading advice. Nothing on this site is financial advice.

How the live pipeline works

  1. Bootstrap — the page loads the latest Actions-verified snapshot (data/topics/*.json) so tables are populated instantly.
  2. Discovery — every ~6 min it pages GET /events?status=open&limit=200 (the verified page size; 1000 is rejected) and classifies events into the five topics using categories + reviewed keyword rules.
  3. Polling — every ~12 s it batch-fetches the watchlist via GET /markets?tickers=… (verified single-response behavior), updates prices, samples, charts, and detects settlements directly from the response.
  4. Alerts — any sampled move ≥ $0.10 posts to the all-events chat; the ROI screen decides what also posts to the model chat; the paper bot reacts per strategy rules.
  5. Detail views — the selected market's order book is polled every ~8 s (bids only, asks derived by the official reciprocal rule) and candlesticks (1-min / 60-min) feed the longer chart windows.

REST responses are cached by the exchange for a short time (official docs), so everything lags the tape by a few seconds; sub-second swings are not observable over REST. See Methods for every parameter and Flagged for every limitation.
