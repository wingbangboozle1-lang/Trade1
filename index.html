Executive summary

Kalshi demo is a separate test environment. This static site reads the public demo REST API (also supported: demo-api.kalshi.co) for open markets, and polls it while a dashboard tab is open. Coverage is limited by title/category keyword matching to five topics: gas prices, elections, culture, crypto, and golf. Events within each topic stay together on their own category page.

It is a live alerting prototype: sampled YES-bid changes of ≥ $0.10 in either direction appear in two scrolling chats — all events and model-liked high-ROI (simulated heuristic, unverified). A live chart plots contract price against time (selectable seconds/minutes/hours window), with current liquidity (contracts available at bid prices). Paper trading lets you test strategies by category and track a simulated portfolio. Resolved markets are tracked until resolution (yes/no outcome).

Not implemented or verified: authenticated demo-account positions, automated order execution, settlement-outcome ingestion, true dollar-notional ranking, persistent WebSocket feed, external-news cause attribution, and GitHub Pages deployment confirmation. See the Flagged for review page.

How the dashboard works

  • Discovery: polls GET /markets?status=open on the demo REST API; results filtered to the five topics by keyword match.
  • Ranking: displayed rows are sorted by the API-reported market contract volume. An official dollar-notional field is not established here, so dollar notional is never inferred (flagged).
  • Alerts: sampled YES-bid changes ≥ $0.10 up or down flow into the all events chat; a simulated model heuristic selects high-ROI candidates into the model likes chat.
  • Chart: X axis = timestamp, Y axis = YES bid price in dollars; choose seconds/minutes/hours window.
  • Liquidity: order-book bid levels show how many contracts are available at a given price.
  • Paper lab: record simulated trades categorized by strategy; portfolio table and simulated cost tracked in localStorage.
  • Resolution: markets are followed until resolved; the outcome (yes/no) is shown when reported by the endpoint.
