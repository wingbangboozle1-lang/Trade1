Requirements coverage matrix

Read this page top to bottom: each row is one requirement line from the brief, quoted, with the page or file that delivers it, the exact rule it runs, and the evidence a reviewer can open. Status meanings: Delivered built and covered by an offline test or an official source; Delivered, with a stated limit built, but something real constrains it and the limit is published (never hidden); Not delivered not built, with the reason stated. Values that could not be confirmed from an official source are left blank here and listed on Flagged for Review. Nothing on this page is estimated.

How to read the evidence column. Official = a Kalshi documentation or fee-schedule page, linked. Code = the file and function that actually runs. Test = an offline check that fails if the behaviour regresses. This matrix was compiled on 2026-11-21 (session 155329c7) by reading the shipped code and re-reading each linked official page; the full line-by-line verification record is reports/VERIFICATION_155329c7.md.

5. Resolution tracking until the event resolves

Brief lineWhere it is deliveredEvidenceStatus
"Focus on tracking live events until the events have resolved. How the event was resolved either yes or no." Two paths: (1) every poll re-reads the watched markets and records result + settlement_ts when the exchange sets them (handleMarketBatch() → M.applyResolutions()); (2) the Actions collector writes the settled universe to data/resolved.json, rendered by resolved.html. Paper positions settle at $1 per winning contract. Official: Market Lifecycle — result is yes/no/scalar; settled markets end at finalized with settlement_ts. Tests: tests/live_fixes.test.mjs D3; tests/live_dash.test.mjs A1b. Delivered
The committed resolved snapshot is trustworthy Fixed this session. The snapshot in the repo was written by a collector run that was rate-limited (220 × HTTP 429, data/log.md), so its settled_total: 0 was an artifact. The collector now paces requests, retries 429 with backoff, and records request_complete; the page shows "INCOMPLETE — collector was rate-limited" instead of "nothing resolved", and no longer skips the live sweep. Official: Rate Limits — "back off on 429". Code: scripts/collect.py get()/_pace(). Test: tests/test_collect.py (5 new tests). Two layers, both published: (1) portfolio.html — the always-on CI ledger (data/portfolio.json); (2) trades.html — the in-browser Strategy Lab. Read the distinction: both are simulations priced from official quotes with the official taker fee. They do not read your demo account balance. Reading the account requires an authenticated demo key. Strategy Lab and Portfolio show P&L, win rate and ROI by strategy and by topic, with an equity curve and a per-trade ledger whose rows carry strategy, topic, side, entry, exit reason and the official record link. Order placement against the demo account exists only in the separate opt-in Demo Account console, and it is inert until you add your own demo API key as repository secrets. Official: API Keys (signing) · Demo Environment (keys are demo-only). No credential is bundled; data/demo_account/status.json records configured: false. Test: tests/demo-account.test.mjs (89 checks). Workflows: pages.yml (checks on push; snapshot every 3 h), portfolio.yml (ledger twice an hour), demo-account.yml (read-only snapshot every 6 h; orders only on manual dispatch with a key). Delivered

10. What is not delivered, stated plainly

ItemWhyWhere it is trackedStatus
Live WebSocket streaming in the page The handshake requires signed headers a browser cannot set. Polling every ~12 s is the documented-compliant alternative; sub-second swings are therefore not observable. Flagged #13, #15, #19 · Ideas proposes a small server-side bridge as the real fix. Not delivered
Reading your demo account balance / positions by default Requires an authenticated demo API key. None is bundled, and the site must not ask you for one in a page. The opt-in console exists and is documented. Flagged 9d-5, I5, #12, E9 · Demo Account. Not delivered by default
Exchange-published traded-dollar amounts The API publishes no such field. Dollar figures are computed and labelled estimates. Flagged #5, E6. Not possible
Verified predictive "high ROI" model The score is a documented heuristic screen. Claiming alpha would be an unsupported inference. Flagged #8, AA-6, F7 · Methods §3. Not claimed
Maker-fee modelling Paper fills assume immediate matching (taker). The maker formula exists in the official schedule but the paper engines do not charge it. Flagged #6, E3, 691-10. Not modelled
