Rate Limits and TiersRe-read 2026-11-21 for the request governor in assets/governor.js. Verbatim rules used: every request costs tokens and the tier sets the per-second budget (Basic Read 200, most GETs cost the default 10 ⇒ ~20 reads/s sustained); buckets are token buckets that “refill continuously … There are no fixed windows and no per-second resets”; Basic/Advanced Read buckets hold three seconds of budget (“you can then spend up to three times your per-second budget in a single burst”); a 429 body is {"error":{"code":"too_many_requests","message":"too many requests"}} and “429 responses carry the rate limit headers, but not Retry-After. There is no penalty or cooldown… Apply exponential backoff on 429”; X-RateLimit-Reset is “Seconds, to the millisecond, until the bucket is full again”; “Publicly cacheable responses (Cache-Control: public), which include most market data, carry none of these headers”; “Unauthenticated public requests are subject to separate limits. Authenticate requests where supported and back off on 429”; batch endpoints “cost the same as making each call individually”. This is what the dashboard’s pacing, backoff and header display implement — see Methods §7.

Contract terms · AAAGASNEW (PDF)Closes F2. Source Agency “the American Automobile Association (AAA), through the daily average fuel price figures published on its AAA Fuel Prices website (gasprices.aaa.com)”; the change is “the figures exactly as published by AAA (currently to four decimal places …) without further rounding”; “Between X and Y” is inclusive of both endpoints; missing publication → use the “Yesterday Avg.” of the following day; a “No data” strike resolves Yes and all others No; Minimum Tick $0.01; Expiration time 10:00 AM ET; Settlement Value $1.00.
Contract terms · AAAGASMINMAX (PDF)Closes F2 (second file). Same AAA source agency but a different contract shape: “the set of average gas prices for regular gas in <area> between Issuance and <date>”, strikes “between 0 and 100”, Minimum Tick 0.001, Expiration time “10:15 AM, 11:00 AM, or 3:00 PM ET”, areas “including the whole United States as well as its states and counties”. The tick, schedule and county-scope differences vs AAAGASNEW are why the site reads per-market close_time instead of assuming one gas schedule.
Kalshi Developer Agreement v1.1 (PDF)Closes F3 (was “Not read”). §1 “Accessing or using Kalshi’s API shall be considered a binding acceptance of this Agreement”; §3 “Use of Kalshi APIs is expressly limited to facilitating a members own trading on the Exchange”; §3.1 prohibits “Collecting, caching, aggregating, or storing data or content accessed via the API except for purposes of facilitating your own trading on Kalshi” and sharing it “with third parties in any manner without prior written authorization”; §3.5 bars “monitoring the availability, performance, or functionality of any of Kalshi’s services or for any other benchmarking or competitive purposes”; §4.3 requires “Retry with exponential backoff, not immediately”, a bounded number of retries, and monitoring “with any dashboards and alerting required”; §5 limits may change “without notice”. Result: one compliance question raised for the owner (this repo stores and publishes snapshots) — see the Flagged page, items F-9b-1/2/3 — and one design confirmation: the collector’s backoff matches §4.3.

Not explained”). “Candlesticks for markets that settled before the historical cutoff are only available via GET /historical/markets/{ticker}/candlesticks”; cutoffs published by GET /historical/cutoff; GET /markets+GET /markets/trades stop returning rows older than market_settled_ts / trades_created_ts; “Old Events and Series will always still be available through their original endpoints.” Explains both the empty-candlesticks probe and why a settled-market archive shrinks by design.

Fixed in this branch: assets/app.js now documents the field and labels that detector “vs 24h reference price”; the matching wording in executive-summary.html is requested to that file’s owner (PR #85/#95). Maximum value is 200” → the “undocumented events page-size ceiling” flag is withdrawn.
Rate Limits and TiersWhy the pipeline backs off the way it does: “Most requests cost the default of 10 tokens”; “Unauthenticated public requests are subject to separate limits. Authenticate requests where supported and back off on 429”; a 429 body is {"error": {"code": "too_many_requests", …}} and “429 responses carry the rate limit headers below, but not Retry-After. There is no penalty or cooldown … Apply exponential backoff on 429.”; X-RateLimit-Reset = “Seconds, to the millisecond, until the bucket is full again”; burst capacity is up to three seconds of budget on Basic/Advanced Read buckets. Consequence recorded: the collector’s Retry-After branch can never fire, and the X-RateLimit-* headers are the signal to use instead.
Batch Get Market Candlesticks“Accepts up to 100 market tickers per request”; total periods ≤ 10,000 or 400 bad_request; “the response is never truncated”; grouped per market_ticker. The cheapest way to cut the collector’s request count (change request R2), and it is the same call a browser can batch for the watchlist.
Get Market CandlesticksConfirms the chart contract: period_interval ∈ 1/60/1440 minutes, ≤ 5,000 periods per request, start_ts/end_ts “must be in seconds; millisecond values are rejected with 400 bad_request”, and “The most recent candlesticks can be a few seconds behind the latest trades and quotes” — the documented reason the seconds/minutes windows plot the trade tape instead.
Get TradesConfirms the tape the charts and jump detection use: limit “1-1000, defaults to 100”, min_ts/max_ts “must be in seconds”, an unknown ticker returns “200 with an empty trades list, not 404”, and “a cursor that cannot be decoded is ignored and the first page is returned”. The Trade schema’s deprecated taker_side is not read anywhere in this repo (checked across assets/**, scripts/**), so no migration is owed.
Orderbook ResponsesConfirms the liquidity ladder: bids only, [price_dollars, count_fp] ascending with “the highest bid (best bid) is the last element”, YES bid at X ≡ NO ask at $1.00−X, and two facts now stated on the site: “Order counts per level are not returned” and an empty yes_dollars/no_dollars array means either no resting orders or a ticker that does not match any market (“returns 200 with empty arrays rather than 404”) — so “no liquidity” and “archived/typo ticker” cannot be told apart from this endpoint alone.
API Environments and Endpoints · Test In The Demo EnvironmentCloses the “WS host naming differs across sources” flag: the official demo pair is wss://external-api-ws.demo.kalshi.co/trade-api/ws/v2 (recommended — the URL in this project’s brief) and wss://demo-api.kalshi.co/trade-api/ws/v2 (also supported), with REST https://external-api.demo.kalshi.co/trade-api/v2 / https://demo-api.kalshi.co/trade-api/v2. Demo caveat quoted by the site: “The price and behavior of markets in the demo environment may not be reflective of those in real markets.” A non-official external-api-demo.kalshi.co string that had crept into docs/api-reference.md was removed.
Quick Start: WebSocketsWhy this site is REST-polled: “even channels that carry public market data still use the authenticated WebSocket session”, so a static page cannot subscribe. Channels and latency hosts recorded from the same page; a handshake 429 “has two causes” (concurrent-connection limit, or connecting too fast) and the documented advice is to “Reconnect with exponential backoff”.
API KeysAuth facts the demo-account track is built against: Ed25519 is recommended, RSA-PSS with “MGF1 with SHA-256, salt length equal to the digest length” is supported; sign the path “without query parameters”; the timestamp “must be within 30 seconds of Kalshi’s clock … Outside that window the request returns 401 with code header_timestamp_expired”. The repo’s demo-account/assets/signer.js implements both algorithms with saltLength: 32 → conformant. The POST /log_in + Basic-token line inherited from a third-party PyPI SDK is not in the official docs and is now marked as unverified legacy behaviour.
Create Order (V2) · Cancel · Amend · DecreaseEvery order path the demo-account console would call, verified: POST /portfolio/events/orders requires ticker, side ∈ bid|ask, count, price, time_in_force, self_trade_prevention_type; “A 201 means the order was accepted, not that it is resting: check remaining_count”; “The legacy /portfolio/orders write endpoints … have been removed and now return 410 Gone with code deprecated_v1_order_endpoint” → closes the demo-account flag that had recorded the 410 behaviour as unverified; amend requires ticker, side, price, count and “an amend that changes nothing returns 400 with code AMEND_ORDER_NO_OP”; decrease takes “exactly one of reduce_by or reduce_to”; cancel auto-routing “requires market_ticker” and “returns {order_id, client_order_id, reduced_by}”.
Fee schedule PDF (last updated and effective July 7, 2026)Re-read to check the fee engine line by line: taker “fees = round up(M × 0.07 × C × P × (1 - P))” (default M = 1), maker “round up(M × 0.0175 × C × P × (1-P))” with “default is 0 unless otherwise indicated”, “There is no settlement fee”, the Non-Standard Fees table (e.g. KXAAAGASM US gas price — maker 1 / taker 1; KXBTCY/KXETHY 0 / 0), and the 21-row worked table ($0.01→$0.01, $0.50→$0.02, $0.99→$0.01 for one contract). The PDF’s own prose says rounding is “to a centicent”, which its table contradicts — the engine follows the table, and the contradiction remains flagged (F-DA-5).
