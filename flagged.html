E1Correction to Flag #1 above — not a contradiction. The demo API returning status: "active" matches the documented market status enum. The four values cited in Flag #1 (unopened / open / closed / settled) are the status= query filter values, and open is documented as matching active. Market Lifecycle (status table + filter mapping) · Get Markets schema
E2Two fee models now exist, deliberately. The published schedule says fees = roundup(M × 0.07 × C × P × (1−P)) with "round up … to a centicent"; the Fee Rounding page defines the trade fee as ceil_6dp(model fee) plus a balance-alignment rounding fee. The CI ledger (scripts/portfolio_engine.py) implements that 6-decimal + $0.01-alignment rule. The browser lab (assets/model.js) still rounds each fee up to a whole cent, which can overcharge by up to $0.0099 per leg — conservative, but the two engines will not produce identical P&L on purpose. Fee schedule PDF · Fee Rounding
E3Maker fees are not modeled anywhere, and for the in-scope gas series they are not zero: the Non-Standard Fees table lists KXAAAGASM (US gas price) with maker multiplier 1 and taker multiplier 1. Any strategy that would rest a limit order in gas markets is therefore mis-priced in both simulators. Fee schedule PDF — Non-Standard Fees
E4The CI ledger samples every ~30 minutes, so its time-based exits are re-tuned (max-hold counted in samples, not minutes) and a fast round-trip that the browser lab catches is invisible to it. Ledger results are a slower-clock test of the same rules, not a copy of the lab's numbers. Portfolio page — "Rules the engine trades by" · workflow
E5Wide-gap alerts. The first live cycle compares against a price seeded from the committed snapshot, which can be hours old; every alert now records the sample gap it was measured over and is labelled wide gap above 90 minutes, so a stale-quote delta is never read as a fast market move. data/portfolio.json → alerts[].gap_minutes
E6Dollar ranking is still an estimate. No per-market dollar-notional field is published, so the highest-dollar ordering uses volume_24h_fp × last_price_dollars and stays labelled "est.". A measured alternative exists (the trade tape, count_fp × yes_price_dollars) but is not yet implemented — see Suggestions #2. Get Markets fields · Get Trades
E7A tape-based ranking cannot be back-filled naively: GET /markets/trades is paginated (limit ≤ 1000, cursor) and its documentation states no ordering guarantee, so "last 24 h of trades for the whole exchange" cannot be claimed from one page. Any implementation must page until min_ts is passed and label the result partial if it stops early. Get Trades — pagination notes
E8Unauthenticated rate limits have no published numbers. The docs say public requests are subject to "separate limits" and to back off on 429. The ledger's pacing (≤ ~1 batched request per ~0.35 s, twice an hour) is a safety choice, not a documented bound. Rate Limits and Tiers
