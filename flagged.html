6Trading fees. RESOLVED during this session: the official fee schedule (kalshi.com/docs/kalshi-fee-schedule.pdf, effective July 7, 2026) defines taker fees as roundup(M × 0.07 × C × P × (1−P)); the paper broker applies exactly that (toggleable). Verified line by line, and one bug found and fixed: the naive float form ceil(0.07·C·P·(1−P)·100) returned $1.76 for 100 contracts @ $0.50 because binary float renders 1.75 as 175.00000000000003 — the official table says $1.75. The fee function now computes in integer arithmetic (price in 1/10000 $, count in 1/100) and reproduces all 21 published price rows of the General Trading Fees Table for both 1 and 100 contracts (automated in tests/root_engine.test.js, run on every push and PR). Still unmodeled: maker fees (roundup(M × 0.0175 × C × P × (1−P))) because paper fills assume immediately-matched orders.Maker path not modeled (documented simplification)official fee schedule PDF
6bPer-series fee structure — verified from the API, not the PDF. The demo API publishes each series’ fee structure: GET /series/{ticker} returns fee_type and fee_multiplier. Every in-scope series checked live reports fee_type: "quadratic" and fee_multiplier: 1 — exactly the general taker rule our model applies (KXBTCY, KXETHY, KXAAAGASM, KXPGATOUR, KXOSCARPIC, KXPRESNOMD; links in Methods §4). Note the published PDF’s “Non-Standard Fees” table lists different multipliers for some of these series (e.g. KXBTCY as 0/0) — those are production values and are not what the demo feed reports, so we follow the demo API. Because the demo reports quadratic (not quadratic_with_maker_fees), resting orders on these series would carry no maker fee, consistent with our model.Series fee structure verified per series from the demo API; production PDF differs for some seriesGet Series List · demo series example
6cFee rounding granularity. The PDF rounds fees so “fee + positionCost is rounded to a centicent”, while the newer Fee Rounding doc describes fees at $0.000001 granularity with a separate rounding fee and rebate accumulator. We round the trade fee up to the nearest cent, which matches the published table exactly but is coarser than the 6-decimal rule — our paper fees are therefore never lower than the exchange’s.Two official descriptions; we use the published tableFee Rounding
