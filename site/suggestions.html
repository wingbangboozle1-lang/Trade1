💡 Suggestions — how to make the site even more live & interactive

The current build already does: live polling, seconds/minutes/hours charts, orderbook depth, ≥ $0.10 jump feed, YES/NO resolution tracking, and automated paper strategies. Ranked suggestions below — each notes the official capability it relies on.

High impact

#SuggestionWhyWhat it needs
1WebSocket streaming (ticker, orderbook_delta, trade channels) Removes REST polling lag entirely; sub-second updates on price and depth; matches how pros watch markets. Demo API keys — official WS requires signed auth (docs); demo WS endpoint already pinned in config.
2Browser notifications + sound on ≥ $0.10 jumps Traders can watch other pages while the site listens; jump alerts become actionable instantly. Notifications API (no backend needed) — the jump detector already exists.
3Sparklines in every table row A 60-second shape per market makes ranking tables scannable without clicking through. Chart.js mini-canvases fed from the same local price history.
4Strategy backtesting on candlestick history Test parameter tweaks against weeks of official 1-min/1-h candles before running live-in-paper. GET candlesticks already integrated (≤5,000 periods/request (docs)).
5Real demo-account execution (paper → real fills) Closes the loop: strategies place genuine demo orders; portfolio page shows the true demo balance/P&L. Demo account + API key (human step), then sign POST /portfolio/orders per Quick Start: Create your first order. Currently flagged F2/F11.

Medium impact

#SuggestionWhyWhat it needs
6Jump→news matching feed Replace labeled news *searches* with auto-fetched headlines per jump (RSS aggregation, no API key). A small serverless proxy (e.g., GitHub Action → committed JSON) since browsers can't fetch arbitrary RSS cross-origin.
7Cross-market arbitrage scanner Within an event, YES+NO asks < $1.00 = risk-free pair; multi-candidate events sometimes misprice. Traders love a scanner panel. Already-fetched orderbooks; add a math pass per event group.
8Trade velocity + large-trade highlights Trades/min and whale-trade flags explain jumps better than price alone. GET /markets/trades already integrated; aggregate client-side.
9PWA + offline cache Installable mobile dashboard; last snapshot viewable offline (clearly timestamped). Service worker + manifest; static site makes this trivial.
10Keyboard command palette Press "/" to jump to any market; number keys to switch topics — power-trader ergonomics. Pure front-end.

Organization & simplification (continuous)

  • Keep topics separate — one subpage per topic (done: gas / elections / culture / crypto / golf); never mix events across topics.
  • One-click triage — the landing page ranks the highest-dollar markets so a trader decides in seconds where to look; topic pages hold the depth.
  • Simplified charts — single price line by default, OHLC on hover only (done); depth chart collapses to best-12 levels (done).
  • Everything sourced — every table row links the exact API call + official Kalshi page (done), so review never blocks trading flow.
  • Flagged items stay visible — persistent "Flagged" nav entry so unverified values are always one click away (done).
