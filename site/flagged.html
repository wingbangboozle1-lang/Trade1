🚩 Flagged for Review

Rule: if a value can't be confirmed from an official source, it is left blank and flagged — never inferred. These items do not block the site; they are published for post-launch review, with source links.

#ItemStatusDetail & mitigation
F1CORS behavior of the demo API is not confirmed by an official statement unverified (behavioral) Official docs publish browser-JS fetch() examples against the API (Quick Start: Market Data), implying browser-origin requests are expected to work, but no doc states Access-Control-Allow-Origin. The build sandbox cannot reach kalshi.co to test headers. Mitigation: the site detects failed fetches, shows a banner linking the exact API URL, and never fakes live data.
F2Demo API credentials do not exist in this session blocked by design Authenticated endpoints (orders, portfolio, WebSocket) require a demo API key (API Keys); creating the demo account is an interactive human step (official tutorial) that cannot be done autonomously. Mitigation: fully automated paper engine on live demo data (official fee formula, $10,000 simulated bankroll); a read-only signed connector is built-in and dormant until keys are supplied locally in the browser.
F3Aggregate "liquidity" field missing from current market responses irregularity Market objects returned by the demo API (spec v3.37.0, verified live 2026-11-20) have bid/ask prices + sizes but no aggregate liquidity field. Mitigation: liquidity is computed from the orderbook (contracts within $0.10 of the best bid per side) and labeled as computed, with the raw orderbook API linked.
F4Status vocabulary differs between filter docs and live field values irregularity GET /markets filter docs allow unopened|open|closed|settled (Get Markets) but live status fields show active/finalized (verified 2026-11-20). Mitigation: app treats active≈open, finalized≈settled and tolerates both vocabularies.
F5News links for price jumps are searches, not verified causes partially verifiable The requirement asks for links that "may have caused" a ≥ $0.10 jump. Without a news API key, attribution cannot be verified. Mitigation: each jump links (a) the official market page/API call, (b) the event's official settlement sources (from the API), (c) a clearly-labeled Google News query.
F6Demo site has no public market webpage for deep links irregularity Demo markets live behind demo.kalshi.co (login); public kalshi.com pages document the production contracts of the same series. Mitigation: row links point to (1) the exact demo REST URL that produced the value and (2) the official kalshi.com series page (URL pattern from official docs).
F7Sub-cent/settlement-bound fields not exercised live unverified at runtime settlement_bounds_type, collateral_return_type values beyond defaults were not observed in live probes. These fields are displayed only when present, never inferred.
F8"Highest dollar amount" ranking metric is a defined approximation methodology (documented) No official "dollar amount per event" metric exists. The site ranks by Open Interest × mid-quote (USD) and also shows 24h $ volume (volume_24h × last price). Raw contract counts are always shown alongside; the formula is printed next to each ranking.
F9KXPRES28 probe failed (fetch-tool error; not API-verified) unverified Two direct probes of GET /series/KXPRES28 errored at the fetch-tool level; the 2028 presidential series is therefore not claimed as verified for demo. Elections coverage uses the verified category Elections + live discovery instead.
F10Client polling can lag the exchange by several seconds documented limitation Official docs state market-data responses are cached briefly and can lag the exchange by seconds (Get Markets, Candlesticks). The site shows a "updated HH:MM:SS" stamp per panel and labels all prices with fetch time.
F11Automated order placement on the real demo account is intentionally dormant unverifiable without credentials Placing orders requires signed demo credentials (F2). Shipping untested order-placement code would violate the no-hallucination rule. Mitigation: the paper engine fulfills simulated-trade requirements; the read-only connector (balance/positions) is live once keys are provided; order placement should be enabled only after credential-based testing.
F12WebSocket streaming not used for live updates documented limitation All WebSocket connections require signed API-key auth (Quick Start: WebSockets). REST polling is used instead; WS is the top upgrade path once demo keys exist (see Suggestions).
